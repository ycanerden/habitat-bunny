## What it does

`picasso` is an elimination pass. It takes a product, a pitch, or a piece of copy and cuts until only the core remains: the locked one-liner, nothing else.

The defining constraint: it does not add and it does not polish. If the after is not shorter than the before, the pass failed.

## When to reach for it

Type `/picasso`, or the agent reaches for it automatically when you are about to launch or talk to customers with extra features still on, when copy is fluffy, or when a page or pitch lists more than the one-liner.

Reach for this when the idea is already locked and the artifact is fat. If the idea is mush, you want [grilling](./grilling.md). If a *new* feature just appeared mid-build, you want [check-scope](./check-scope.md): that parks one incoming idea. Picasso hunts everything that is already there and should not be.

| You have… | Use |
| --- | --- |
| A shiny add during build | [check-scope](./check-scope.md) |
| A kitchen-sink product, pitch, or landing page | `picasso` |
| No one-liner yet | [grilling](./grilling.md) |

## The bull is a few lines

Picasso could draw a bull without the meat. Habitat uses that as a rule: shade last, and usually never. The leftover is what you show a customer. The rest goes to the backlog or the bin.

## Common questions

**Is this only for code?**
No. Run it on a tweet, a hero paragraph, a demo script, a first DM. Copy is the usual surface. Features are the other.

**Will it delete my settings page?**
If settings are not the one-liner, yes, or it will tell you to hide them and park the work. Explaining a parked feature to a customer is how it comes back.

**What if I need those features next week?**
Park them. [check-scope](./check-scope.md) writes `.habitat/backlog.md`. Picasso is tonight and the first conversation, not the roadmap.

## It's working if

- The after is shorter, and you can point at what died.
- You can say the one-liner without "and also".
- A stranger would not notice a missing settings page because you never mentioned it.
