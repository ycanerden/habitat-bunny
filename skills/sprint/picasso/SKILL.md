# Picasso

The Picasso tactic. Named after *Le Taureau*: Picasso drew a full bull, then redrew it eleven times, each state with less, until a few lines were still unmistakably the bull. Nothing was added between states. Only removed.

That is the whole method. You do not rewrite, simplify, or polish. You delete, and you check.

## The one test

Take a piece out. Read what is left.

- Meaning intact: the deletion stays. Take out the next piece.
- Meaning lost: put it back. Try a smaller piece inside it.

Stop when every remaining piece fails the test. That is the core. One more cut would break it.

The test is the same at every scale. A word in a sentence. A sentence in a paragraph. A step in a plan. A feature in a product. Pick the scale of the thing in front of you and work down.

## Work in states

Show the cut as numbered states, like the lithographs. State 1 is what they gave you. Each state is shorter than the last. The final state is the one where nothing else can go.

For a sentence, two or three states. For a page or a product, as many as it takes, but each state must remove something real. A state that only rewords is not a state. Skip it.

Always show the last state next to the first. The last must be shorter. If it grew, you failed the pass. Do not explain what you removed unless asked. Absence is the point.

## Name the core first

Everything you keep must serve one thing. For a sprint that is the locked one-liner: read `.habitat/sprint.md` if it exists. For a sentence it is the one fact the sentence exists to carry. For a plan it is the deliverable. For a pitch it is the one promise.

If they cannot name it, do not invent it. Ask: "What is the one thing this has to do?" For a product with no lock, call the Skill tool with "grilling". Picasso does not run on mush.

## Surfaces

| You were handed | You are hunting | You leave behind |
| --- | --- | --- |
| a sentence | hedges, adjectives, doubled words, throat-clearing, "in order to", "there is" | the fact, in the ICP's own verbs |
| copy: a hero, a tweet, an email, a README | every second benefit, every claim without a number, every word that survives deletion | the one promise, in fewer words |
| a plan: today's list, a spec, a PR description, a sprint scope | every step that does not move the deliverable to a URL | the deliverable and the steps that touch it. The rest is parked |
| customer talk: a pitch, a demo, a first DM | the company intro, the tour, the second ask | one promise, one action, nothing to apologize for |
| a product | screens, settings, "also we built", the hidden menu | what a stranger can touch tonight. Everything else parked |

Detect the surface from what they pasted or pointed at. If unclear, ask once, then cut. Do not switch surfaces mid-pass.

## Rules

- Delete beats hide. Hidden in a menu is not gone. If it must live, park it: call the Skill tool with "check-scope" for that item.
- Do not replace. A shorter adjective for a long one is not a cut. A "coming soon" where a feature was is not a cut.
- Kill on sight: empower, seamless, revolutionary, next-gen, unlock, leverage, delightful, robust, easily, just, simply, very, really, actually, basically, "we help you", "in order to", "the fact that".
- Prefer the number you can stand behind to the adjective you cannot.
- If a sentence does not name a person, a moment, or the one action, it goes.
- For a plan: if a step can be done after the URL exists, it is not tonight. Park it.

## Before launch or customers

If they are about to ship, demo, or DM someone: run the product surface, then customer talk, in that order. Do not let them explain a parked feature to a stranger. The explanation is the feature coming back.

Then, if they still need a URL recorded, call the Skill tool with "ship".
